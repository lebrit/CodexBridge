# Security policy

## Supported versions

The latest published prerelease receives security fixes. Older prereleases may be replaced rather than patched separately while the project is before version 1.0.

## Reporting a vulnerability

Please use the repository's private **Security** tab and create a private vulnerability report through GitHub Security Advisories. Do not open a public issue for an unpatched vulnerability and do not include real recovery keys, passwords, tokens, personal paths, or private project data.

Include the affected version, impact, prerequisites, minimal reproduction, and any suggested mitigation. The maintainer will acknowledge a complete report when it is reviewed and will coordinate disclosure after a fix or documented mitigation is available.

## Release trust

Public releases include a SHA-256 checksum. Current binaries are unsigned unless both the release notes and Authenticode signature prove otherwise. See [CODE_SIGNING_POLICY.md](CODE_SIGNING_POLICY.md).
