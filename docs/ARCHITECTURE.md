# Архитектура CodexBridge

## Граница продукта

CodexBridge создаёт резервные копии и восстанавливает рабочую среду, но не клонирует Windows и не переносит учётные данные. Источником текущего состояния служит файловая система, каталог CodexBridge хранит намерение защищать проект, а restic-снимки являются историей.

Удаление проекта из другого приложения не удаляет файлы или backup. Пропавший путь получает состояние `Missing`; окончательное удаление снимков не выполняется автоматически.

## Компоненты

- `CodexBridge.App` — WPF GUI;
- `CodexBridge.Agent` — короткоживущий фоновый процесс Планировщика Windows;
- `CodexBridge.Core` — обнаружение, backup, restore, DPAPI и безопасное слияние;
- `CodexBridge.Tests` — минимальные проверки путей и конфликтов.

Постоянной Windows-службы, собственной БД, облачного backend и plugin SDK нет. Состояние хранится атомарными JSON-файлами в локальном профиле пользователя.

Главный экран сводит состояние restic, ключа, хранилищ, проектов и Планировщика Windows в один пользовательский статус. Все длительные действия GUI проходят через общий `RunBusyAsync`, который блокирует повторные команды и показывает единый индикатор операции. Последние десять результатов сохраняются в `BackupState`, а обзор показывает шесть самых свежих записей.

Экран проектов фильтрует основную `ObservableCollection` через стандартный WPF `ICollectionView`: фильтр не создаёт второй каталог и не влияет на состав резервной копии. Массовые изменения применяются только к видимым строкам и записываются в каталог после явного нажатия «Сохранить выбор».

## Backup flow

1. Обновляется каталог проектов.
2. В snapshot manifest записываются логические проекты и безопасные элементы среды.
3. Вложенные корни сворачиваются, чтобы не читать файлы дважды.
4. Restic создаёт локальный зашифрованный снимок.
5. Если облако включено, создаётся второй снимок через rclone backend.
6. При включённой политике хранения restic удаляет только лишние снимки с тегом `codexbridge`, сохраняя заданное число дневных, недельных и месячных версий.
7. Локальный и облачный результаты учитываются отдельно.

Два чтения исходников в локальное и облачное хранилище — сознательное упрощение первой версии. Переход на `restic copy` оправдан после проверки стабильности cloud flow.

## Restore flow

Снимок сначала извлекается во временный каталог приложения. Manifest сопоставляет старые абсолютные пути с новым корнем проектов. Отсутствующие файлы создаются, совпадающие пропускаются, отличающиеся входящие версии помещаются в `.codexbridge-conflicts`. После успешного слияния временный каталог удаляется.

## Секреты

Рабочая копия ключа restic защищена Windows DPAPI для текущего пользователя. Она не входит в snapshot и публичные артефакты. Содержимое ключа не передаётся через аргументы командной строки. Restic получает его только в окружении дочернего процесса.

## Необязательные инструменты

WinGet используется для фиксации и восстановления списка приложений. VS Code не является зависимостью CodexBridge: элементы его интерфейса появляются только после обнаружения установленного редактора, а настройки и расширения переносятся только по выбору пользователя. Rclone также необязателен и нужен лишь для второй копии в выбранном пользователем облаке.
