# Ручная приёмка CodexBridge

Этот чек-лист закрывает только те риски, которые нельзя честно проверить на одноразовых GitHub runners. Автоматические проверки выпуска описаны в [`RELEASE_TESTS.md`](RELEASE_TESTS.md).

## Правила безопасности

- Не используйте единственный экземпляр важного проекта для первого испытания.
- До начала сохраните независимую копию исходных данных и ключ восстановления отдельно от проверяемого компьютера.
- Восстанавливайте сначала в новую пустую папку. Не удаляйте исходники, пока не сверены файлы и не открыт проект.
- Не прикладывайте к публичной задаче ключ, настройки, журналы с личными путями или настоящий диагностический архив без проверки содержимого.
- При неожиданном результате остановитесь: повторный запуск должен быть безопасным, но не заменяет разбор причины.

## A. Проверка на текущем компьютере

- [ ] Скачать установщик и `.sha256` из одного релиза, вручную сверить SHA-256.
- [ ] Установить поверх предыдущей версии, если она есть; убедиться, что настройки и каталог проектов сохранились.
- [ ] Пройти обычный мастер настройки и проверить светлую/тёмную темы, клавиатурную навигацию и масштаб Windows 100%, 125% и 150%.
- [ ] Найти проекты только в выбранных корнях; убедиться, что лишние каталоги можно исключить.
- [ ] Создать локальный снимок, выполнить обычную и глубокую проверку.
- [ ] Выполнить dry-run и восстановить выбранный проект в новую пустую папку.
- [ ] Сравнить число файлов и открыть восстановленный проект обычным рабочим инструментом.
- [ ] Повторить восстановление: одинаковые файлы не должны дублироваться, отличающийся локальный файл не должен быть молча перезаписан.
- [ ] Включить автозапуск, перезагрузить Windows и убедиться, что фоновое задание появляется в журнале приложения.
- [ ] Создать диагностический ZIP, распаковать его самостоятельно и убедиться, что в нём нет ключа, списка проектов, токенов, e-mail, URL облака и личных путей.
- [ ] Удалить приложение и убедиться, что пользовательские настройки и снимки сохранились.

## B. Чистая Windows 11 VM

- [ ] Установить только CodexBridge на поддерживаемой Windows 11 x64 без заранее установленного restic/rclone.
- [ ] Выбрать единый новый корень проектов и режим «Восстановить всё на новом компьютере».
- [ ] Указать существующий репозиторий и заранее сохранённый ключ; мастер не должен создавать пустой репозиторий или новый ключ.
- [ ] Сначала выполнить проверку и dry-run, затем восстановить проекты в единый корень.
- [ ] Просмотреть план приложений и среды; применить только недостающие элементы.
- [ ] Повторно войти в Codex, GitHub и облако вручную. Пароли, OAuth-сессии и активная база Codex переноситься не должны.
- [ ] Повторить применение профиля среды: установленные приложения, PATH, Git-настройки и расширения не должны дублироваться.
- [ ] Проверить Codex, MCP, Graphify, Codebase Memory, Ponytail и Obsidian; старые машинные пути не должны применяться автоматически.
- [ ] Ограничить виртуальный диск безопасным размером и проверить понятное сообщение при нехватке места без риска для основной системы.

## C. Облако и физический переезд

- [ ] Настроить отдельный тестовый rclone remote и создать вторую копию после локальной.
- [ ] Прервать сеть во время передачи, затем повторить операцию и проверить целостность репозитория.
- [ ] На другом компьютере скачать только приложение, подключить облачное хранилище и использовать ранее сохранённый ключ.
- [ ] Выполнить полную глубокую проверку и восстановление хотя бы одного проекта до начала массового переноса.
- [ ] После полного переезда открыть несколько проектов разных типов и выполнить их обычную сборку или запуск.

## Фиксация результата

Для каждой проверки запишите дату, версию CodexBridge, выпуск Windows, шаг, результат `PASS`/`FAIL` и ссылку на задачу при ошибке. Скриншоты и диагностические файлы храните приватно до проверки на персональные данные.

Релиз можно считать кандидатом на стабильную `1.0`, когда разделы A и B пройдены без критических ошибок, а раздел C подтверждён хотя бы одним реальным переносом между двумя компьютерами.
