# Проверки выпуска

## Автоматический маршрут

`build → acceptance (Windows Server 2022 + 2025)`

`migration-source (Windows Server 2022) → migration-destination (Windows Server 2025)`

`build + acceptance + migration-destination → publish`

Сборка выполняет unit-тесты, настоящую restic-лабораторию в изолированных каталогах, проверку публичных файлов, публикацию self-contained приложений, проверку GUI и создание ZIP/установщика с SHA-256.

Независимый маршрут миграции не использует рабочие файлы: первый runner создаёт три синтетических файла и зашифрованный репозиторий, второй получает только CI-артефакт, выполняет `check --read-data-subset=100%`, restore `--verify`, сверяет SHA-256 и проверяет повторный запуск. Отчёт сохраняется на 14 дней, исходный зашифрованный артефакт — на один день.

Каждый приёмочный runner получает только пакеты текущей сборки. Предыдущий публичный установщик 0.9.0 скачивается отдельно и проверяется по закреплённому хешу. Проверяются версии бинарников и регистрации установщика, обновление, повторная установка, сохранность контрольного файла профиля, удаление своего задания и сохранение чужого задания с тем же именем. Реальные пользовательские данные в CI не используются.

## Проверка GUI

`scripts/Test-ReleaseSmoke.ps1 -PublishDirectory <папка сборки>` запускает приложение с `--smoke-test <новая папка отчёта>`. Проверяются 24 состояния главного окна (6 страниц × 2 темы × 2 размера), 6 состояний обычного мастера и 6 состояний режима нового компьютера (по 3 шага × 2 темы). Окна не принимают мышь и открываются за пределами рабочего стола; профиль и защищённый ключ не читаются. Проверки используют штатный XAML и WPF, без отдельного браузера или UI-библиотеки.

Отчёт содержит 36 PNG и `success.txt`; при исключении создаётся `failure.txt`. Скрипт требует успешного кода завершения и полного отчёта. Контраст поля хранилища проверяется по относительной яркости цветов; положение кнопок мастера — по фактическим границам после layout; у ключевых полей и кнопок проверяются доступные имена. Это проверка отрисовки, а не имитация полного пользовательского сценария.

В GitHub Actions отчёты GUI и журналы установщика доступны в артефактах `gui-build-*` и `acceptance-*` в течение 14 дней, включая неудачные запуски. Перед публикацией сторонних ручных отчётов следует проверить их на персональные данные.

Проверки, которые требуют обычной Windows 11, настоящего облачного remote или второго физического компьютера, вынесены в отдельный [`чек-лист ручной приёмки`](MANUAL_ACCEPTANCE.md). Он начинается с восстановления в новую пустую папку и не требует удалять исходные проекты.

## Ограничения

- Windows Server runners содержат предустановленные инструменты; это не чистая Windows 11.
- Настоящие облачные учётные записи, логин Codex, DPAPI-перенос между пользователями и внешние MCP не проверяются на чужих секретах.
- Реальное заполнение диска не воспроизводится на runner; вместо опасного заполнения проверены детерминированные ветки `IOException`, заблокированный файл, недоступный каталог, отмена, перезапуск и оборванный журнал.
- Нужна будущая ручная приёмка клавиатуры, экранного диктора, масштабирования DPI и полного восстановления на другом компьютере.
- Публичные пакеты пока не имеют доверенной Authenticode-подписи.

Порядок выполнения обновлённого `UninstallRun` после установки поверх старой версии основан на штатном [`RunOnceId` Inno Setup](https://jrsoftware.org/ishelp/topic_runsection.htm): используется последняя запись с тем же идентификатором.
