# Проверка надёжности — 0.11.1

Дата: 2026-10-25. Целевой аудит восстановления, журналов отката, записи JSON, резервного копирования, установки программ и обновлений. Это не заявление об исчерпывающем аудите безопасности всего приложения.

## Исправлено

| Приоритет | Проблема | Решение |
| --- | --- | --- |
| P1 | Лексическая проверка пути не замечала Windows junction/symlink; копирование или откат могли затронуть другой каталог | Проверка существующих компонентов пути перед чтением, записью и удалением. Небезопасные записи отката сохраняются с состоянием `RollbackBlocked`; остальные безопасные записи обрабатываются |
| P1 | Имена проектов `..` и идентификаторы журналов с точками допускали выход из ожидаемой папки | Безопасные имена проектов, обработка зарезервированных Windows-имён, запрет неоднозначных идентификаторов журналов |
| P1 | GUI и агент использовали общий `.tmp`; параллельные записи конфликтовали | Уникальный временный файл, сброс данных на диск, атомарная замена, совместимое чтение, ограниченные повторы Windows rename, уборка своего временного файла |
| P2 | Обычное восстановление не включало дополнительный restic `--verify`, хотя dry-run включал | Проверка извлечённых данных включена и для рабочего восстановления |
| P2 | Включённое облако без адреса пропускалось, но результат обещал две готовые копии | Проверка конфигурации до запуска backup с понятным сообщением |
| P2 | Ошибка экспорта среды скрывалась за успешным backup | Результат явно сообщает о неполном профиле; успешная копия файлов сохраняется, очистка старых снимков не запускается |
| P2 | При отмене облачного этапа терялась отметка уже готовой локальной копии | Время локального и облачного снимка сохраняется сразу после завершения соответствующего этапа, отдельно от итогового успеха |

Нормализация ACL использует `icacls /L`, то есть обрабатывает ссылку, а не её цель ([документация Microsoft](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/icacls)). Рекурсивный поиск manifest и обработка атрибутов каталогов пропускают reparse points. Ссылки внутри восстанавливаемого дерева не разыменовываются; выбранный корень и пути назначения со ссылками отклоняются.

## Границы защиты

- Для восстановления выбирайте обычную локальную папку. Перенаправленные профили и облачные placeholders тоже могут иметь атрибут reparse point и потребовать другой папки.
- Повторная проверка путей уменьшает риск, но не заменяет изоляцию от другого процесса, который намеренно подменяет каталоги между проверкой и файловой операцией. Не изменяйте структуру папок параллельно с восстановлением.
- Атомарная запись гарантирует целый JSON-документ, а не объединение конкурирующих изменений полей: действует последняя успешная запись.
- Проверки используют только временные синтетические данные. Реальные проекты, облако, установка стороннего ПО и секреты пользователя не задействованы.

## Следующие этапы по полезности

1. **Автоматика и состояние:** сохранять корни временно отключённых дисков; сериализовать read-modify-write состояния между GUI и агентом; показывать отдельные состояния локальной копии, облака и профиля среды.
2. **Экран программ:** прогресс и результат каждого пакета, повтор только неудачных пунктов, понятные состояния «уже установлено», «нужен вход», «требуется перезапуск». Добавить ограничение времени отдельных внешних команд и объёма их вывода. Не запускать установку автоматически без выбора пользователя.
3. **Облако и обновления:** рассмотреть перенос одного готового локального снимка в облако вместо повторного чтения меняющихся проектов; добавить таймаут чтения тела загрузки обновления, уникальный partial-файл и более строгую проверку адресов релиза.
4. **Визуальная приёмка Windows 11:** клавиатура, экранный диктор, DPI 125/150/200%, длинные пути и названия, сон/пробуждение, отключение сети, реально заполненный диск. CI на Windows Server этого не заменяет.
5. **Физический перенос:** отдельный компьютер, настоящее облако, повторный вход в аккаунты. Доверенная подпись остаётся отдельным вопросом сертификата, а не программной доработкой.

Не добавлялись новые зависимости, фоновое полное сканирование дисков или новая постоянная служба. Сначала устраняются риски потери данных, затем улучшается удобство интерфейса.
