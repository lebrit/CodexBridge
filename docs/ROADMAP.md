# Дорожная карта CodexBridge

План скорректирован после появления рабочего приложения. CodexBridge использует restic как проверенный зашифрованный формат снимков и не разрабатывает собственный контейнер или криптографию.

## Готово

- быстрый поиск проектов только в выбранных корнях;
- локальные и облачные зашифрованные снимки;
- безопасное слияние без перезаписи отличающихся файлов;
- мастер настройки, светлая и тёмная темы;
- фоновый агент, Планировщик Windows и автоматическое обновление каталога;
- WinGet-инвентаризация, базовый перенос Codex и необязательный VS Code;
- журнал ошибок, тесты и автоматические ZIP-релизы GitHub.

## Этап 3A — проверяемое восстановление

- полная пробная выгрузка выбранного снимка во временный каталог с `restic --verify`;
- проверка recovery manifest, проектов и элементов среды;
- гарантированная очистка временных данных;
- постоянное предупреждение о последней ошибке и понятная индикация долгой операции.

## Этап 3B — точный план восстановления и отмена

- проверенный dry-run с точным подсчётом add/identical/conflict/skip без записи в рабочие папки;
- результат проверки привязан к конкретному снимку, а перед восстановлением показывается предупреждение об устаревшем dry-run;
- отмена длительных операций завершает дочерний процесс restic и не записывается как ошибка.

## Этап 3C — транзакционное восстановление

- защитная модель назначения: существующие отличающиеся файлы вообще не перезаписываются, поэтому отдельная дублирующая копия оригинала для текущего режима не требуется;
- запись намерения и SHA-256 на диск до создания каждого файла;
- автоматический rollback при штатной ошибке или отмене, обнаружение незавершённой операции после аварийного перезапуска;
- проверенный ручной откат удаляет только файлы с неизменившимся SHA-256 и сохраняет пользовательские изменения;
- журнал транзакций, состояние, назначение и кнопка отката отображаются в интерфейсе.

Перед добавлением любого будущего режима с перезаписью файлов обязательна физическая защитная копия заменяемого содержимого. Такой режим сейчас отсутствует и не будет добавляться скрыто.

## Этап 4A — локальная лаборатория миграции

- временная изолированная «машина A» с двумя проектами, recovery manifest и безопасной конфигурацией Codex;
- два настоящих зашифрованных restic-снимка, `check --read-data-subset=100%`, retention и восстановление с `--verify`;
- перенос в чистую временную «машину B» и проверка файлов по SHA-256;
- повторный запуск не создаёт дубликаты, не перезаписывает локальное изменение и сохраняет версию из снимка в конфликтном каталоге;
- после restic restore приложение сбрасывает ACL только внутри временного staging, устраняя недоступные каталоги при переносе между разными Windows SID;
- лаборатория обязательна для GitHub-релиза и полностью удаляет свои временные данные после проверки.

## Этап 4B — перенос среды разработки

### Готово в 4B.1

- отдельная переносимая копия `config.toml`: MCP env/headers, token/password/secret и credential-настройки удаляются до snapshot;
- глобальные AGENTS/override, rules, memories и пользовательские skills;
- Git-профиль по строгому allowlist с проверкой ключей и значений перед применением;
- реестр Obsidian vault сохраняется как справочная копия, но старые абсолютные пути не применяются;
- recovery manifest schema 2 явно перечисляет исключённые секреты и обязательные ручные действия;
- настоящая A→B лаборатория восстанавливает несколько элементов среды общим циклом, а не специальным кодом только для `config.toml`.

### Далее в 4B.2

- диагностика MCP после восстановления без попытки переноса секретов;
- обнаружение и переустановка Graphify, Codebase Memory и Ponytail;
- пересборка машинных индексов вместо слепого копирования;
- проверка и перепривязка Obsidian vault к единому корню проектов.

## Этап 5 — приложения и повторяемость

- идемпотентное восстановление WinGet-приложений;
- версии Git, Python, Node.js и Java;
- безопасное восстановление PATH и разрешённых переменных;
- проверки второго запуска на уже восстановленном компьютере.

## Этап 6 — установка и уведомления Windows

- MSIX/установщик, обновление и удаление без удаления пользовательских снимков;
- доверенная подпись после появления достаточных публичных сигналов и одобрения Foundation либо отдельного решения о платной подписке;
- системные toast-уведомления с корректной Windows app identity;
- проверка установки и обновления на чистой Windows VM.

## Этап 7 — приёмочные испытания

- VM A → backup → чистая VM B;
- затем физический новый компьютер;
- проверка проектов, Codex, Git, MCP, Graphify, Codebase Memory, Obsidian и приложений;
- итоговый отчёт и исправление найденных расхождений.

Системные toast-уведомления не имитируются через `msg.exe`, PowerShell или временный tray-процесс: такие варианты ненадёжны для фонового задания. До этапа установщика приложение показывает постоянное предупреждение при следующем открытии.
