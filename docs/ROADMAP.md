# Дорожная карта CodexBridge

План скорректирован после появления рабочего приложения. CodexBridge использует restic как проверенный зашифрованный формат снимков и не разрабатывает собственный контейнер или криптографию.

## Готово

- быстрый поиск проектов только в выбранных корнях;
- локальные и облачные зашифрованные снимки;
- безопасное слияние без перезаписи отличающихся файлов;
- мастер настройки, светлая и тёмная темы;
- фоновый агент, Планировщик Windows и автоматическое обновление каталога;
- WinGet-инвентаризация, базовый перенос Codex и необязательный VS Code;
- журнал ошибок, тесты и автоматические ZIP-релизы GitHub.

## Этап 3A — проверяемое восстановление

- полная пробная выгрузка выбранного снимка во временный каталог с `restic --verify`;
- проверка recovery manifest, проектов и элементов среды;
- гарантированная очистка временных данных;
- постоянное предупреждение о последней ошибке и понятная индикация долгой операции.

## Этап 3B — точный план восстановления и отмена

- проверенный dry-run с точным подсчётом add/identical/conflict/skip без записи в рабочие папки;
- результат проверки привязан к конкретному снимку, а перед восстановлением показывается предупреждение об устаревшем dry-run;
- отмена длительных операций завершает дочерний процесс restic и не записывается как ошибка.

## Этап 3C — транзакционное восстановление

- резервная копия затрагиваемого назначения;
- журнал шагов, восстановление после аварийного завершения и проверенный rollback;
- отображение подробного плана и журнала восстановления в интерфейсе.

## Этап 4 — перенос среды разработки

- безопасные настройки Codex, AGENTS, memories и пользовательские skills;
- Obsidian, Git metadata и расширенная проверка VS Code;
- Graphify, Codebase Memory и Ponytail с пересборкой машинных индексов вместо слепого копирования;
- отчёт о компонентах, которые требуют повторного входа или ручного действия.

## Этап 5 — приложения и повторяемость

- идемпотентное восстановление WinGet-приложений;
- версии Git, Python, Node.js и Java;
- безопасное восстановление PATH и разрешённых переменных;
- проверки второго запуска на уже восстановленном компьютере.

## Этап 6 — установка и уведомления Windows

- MSIX/установщик, обновление и удаление без удаления пользовательских снимков;
- подпись SignPath после одобрения;
- системные toast-уведомления с корректной Windows app identity;
- проверка установки и обновления на чистой Windows VM.

## Этап 7 — приёмочные испытания

- VM A → backup → чистая VM B;
- затем физический новый компьютер;
- проверка проектов, Codex, Git, MCP, Graphify, Codebase Memory, Obsidian и приложений;
- итоговый отчёт и исправление найденных расхождений.

Системные toast-уведомления не имитируются через `msg.exe`, PowerShell или временный tray-процесс: такие варианты ненадёжны для фонового задания. До этапа установщика приложение показывает постоянное предупреждение при следующем открытии.
